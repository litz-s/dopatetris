# ドパガキテトリス MVP仕様書

確定日: 2026-07-27 / ステータス: **承認済み**

---

## 1. プロジェクトの目的

ライン消去のたびに視覚・聴覚・触覚的な快感が返ってくる、1人用のブラウザテトリス。通常のテトリスに「イベントスタック」という独自の蓄積・爆発システムを載せ、レトロ×ファミコン×EDMの演出で「ドーパミンが出る」体験を成立させる。

## 2. 対象ユーザー

- テトリス経験があり、より刺激的な派生を求めるPCゲーマー
- 演出やグラフィックの質でゲームを選ぶ層
- 想定環境: PC（キーボード＋マウス必須）、モダンブラウザ（Chrome / Edge / Firefox / Safari 最新）

## 3. MVPに含める機能

### 3-1. テトリス基本

| 項目 | 仕様 |
|---|---|
| 盤面 | 10×20（上部に不可視バッファ2行） |
| ミノ | 7種、SRS（標準回転システム）＋壁蹴り |
| 生成 | 7-bag方式、シード固定可能な決定論的RNG |
| ゴースト | 落下予定位置を半透明表示 |
| ホールド | 1個（1ミノにつき1回まで）。イベント付きミノはイベントの種類・付着位置も保持する |
| Next表示 | 5個 |
| ロックディレイ | 0.5秒、移動/回転でリセット（上限15回） |
| T-Spin | 判定あり（Single / Double / Triple） |
| ライン消去ディレイ | **710ms**（ポップ480ms＋段落下230ms）。この間は入力も落下も止まる |
| 重力ディレイ | **558ms**（列遅延32ms×9＋落下270ms）。ハート3の発動時のみ。この間も入力が止まる |
| ゲームオーバー | スポーン位置にブロックが重なった時点 |

ライン消去ディレイと重力ディレイは、演出（左→右に1個ずつポップ／列ごとにずらして落下）を
成立させるためのゲームルールであり、決定論を保つため core 側の状態として持つ。
どちらも「盤面はまだ変えず、演出終了時にまとめて適用する」方式で実装する。

### 3-2. 操作（デフォルトキーバインド）

デザイン案（3e CONFIG / KEYBIND）を正とする。マウスにも操作を割り当てる。

| 操作 | キー | マウス |
|---|---|---|
| 横位置決定 | A・D / ← → | **カーソルX座標追従**（既定） |
| 回転（右 / 左） | W / S | — |
| ソフトドロップ | ↓ | — |（自然落下の12倍、最短35ms／1ステップ最大2マス）
| ハードドロップ | Space | 左クリック |
| ホールド | Shift | ホイール |
| イベントスタック発動 | E | 右クリック |
| イベントスタック破棄 | Q | — |
| ポーズ | Esc | — |

- 全キーは設定画面で再割り当て可能（localStorage保存、重複検出あり）
- マウス追従は設定でON/OFF可能。追従の滑らかさを 0〜1 で調整（既定 0.35）
- DAS 133ms / ARR 10ms（キー操作時、調整可能）
- キー操作中はマウス追従を一時停止し、競合させない
- 押されたキーは画面左下の **KEY LOG** に表示する（音ゲー的フィードバック）

### 3-3. イベントスタック（独自要素）

#### タイル生成

7-bag 1セットにつき2個のミノに、イベントタイルが1つ埋め込まれる（≒28.6%）。種類は爆弾・ハート・コイン・クローバーの4種から均等抽選。

#### 蓄積ルール（種類ロック方式）

1. スタックが空の状態でイベントタイルを消すと、その種類が**カレント種別**としてロックされる
2. 以降、**同種のみ**が加算される（爆弾・クローバーは上限4、ハート・コインは上限3）
3. 異種タイルを消しても加算されず、ボーナススコア（50 × レベル）に変換される
4. 「最初に消された種類」の判定のため、**ライン消去アニメは常に左→右**に進行し、同一フレームで複数列消去時も左のタイルが優先される
5. 発動、または破棄キー（Q）でカレント種別が解除され、次に消したイベントが新たなロックとなる

#### 効果テーブル（到達した最高段階の効果のみ適用。下位効果は累積しない）

| 種別 | 数 | 効果 |
|---|---|---|
| 爆弾 | 1 | 最下層1列を削除 ＋ 3秒フィーバー |
| 爆弾 | 2 | 最下層2列を削除 ＋ 5秒フィーバー |
| 爆弾 | 3 | 最下層3列を削除 ＋ 7秒フィーバー |
| 爆弾 | 4 | 最下層4列を削除 ＋ 9秒フィーバー |
| ハート | 1 | 到着待ちのおじゃまを1列除去 |
| ハート | 2 | ハート1へフォールバックし、全スタックを消費 |
| ハート | 3 | 到着待ちのおじゃまを1列除去 ＋ 発動時に1回だけ重力を発生 |
| コイン | 1 | 7秒間、落下速度10%低下 |
| コイン | 2 | 7秒間、落下速度15%低下 |
| コイン | 3 | 7秒間、落下速度20%低下 |
| クローバー | 1 | **効果なし（不発）** |
| クローバー | 2 | 10秒フィーバー ＋ コンボ成立ごとにコンボ係数を +0.05 |
| クローバー | 3 | クローバー2へフォールバックし、全スタックを消費 |
| クローバー | 4 | 10秒フィーバー ＋ コンボ成立ごとにコンボ係数を +0.15 |

- 未定義段階は直下の定義済み段階へフォールバック（表内に反映済み）
- **クローバー1で発動キーを押した場合はスタックを消費せず不発**（無駄打ち防止）
- クローバーのコンボ係数は発動時に0.15へ戻り、10秒の効果時間だけ段階的に上昇する。爆弾でフィーバー全体が延長されても、クローバー由来の10秒終了時に0.15へ戻る
- 発動後クールタイム **10秒**（HUDにゲージ表示）
- **フィーバータイム**: スコア1.5倍、コンボが途切れない。重複発動時は残り時間に**加算**（上限15秒）
- **重力**: 浮いているブロックを列単位で下詰めし隙間を埋める。連鎖消去が発生した場合もコンボに加算
- **爆弾の列削除**: 盤面最下段からN行を消去。スコアは加算されるがコンボ数には影響しない
- **ハートのおじゃま除去**: 到着待ちのおじゃまがなければ空振りし、スタックは通常どおり消費する。ソロでは実質的にハート3の重力だけが効果を持つ

### 3-4. スコア

```
ライン消去基礎点 = { 1列:100, 2列:300, 3列:500, 4列:800 } × レベル
T-Spin基礎点     = { Single:800, Double:1200, Triple:1600 } × レベル
コンボ倍率       = 1 + コンボ係数 × コンボ数   (コンボ係数の既定は 0.15)
フィーバー倍率   = 1.5（非フィーバー時は 1.0）
獲得スコア       = 基礎点 × コンボ倍率 × フィーバー倍率
ドロップ点       = ソフト 1点/マス、ハード 2点/マス
```

- コンボ数: 連続消去2回目で1、以降+1。消去しないミノを置いた時点で0にリセット（フィーバー中は維持）
- レベル: 10ライン消去ごとに+1。落下速度はテトリスガイドライン準拠のカーブ

### 3-5. 表示（HUD）

Next 5個 / ホールド / スコア / ハイスコア / レベル / ライン数 / コンボ数 / **カレントイベントスタック（種別アイコン＋蓄積数＋クールタイムゲージ）** / フィーバー残り時間バー

### 3-6. 演出（デザイン準拠）

実装値の出典は `docs/design/design-spec.html`。数値はそのまま実装に使う。

**中心原則: 光るのはブラウン管の中だけ。** クリーム樹脂の筐体面には glow を一切かけず、
厚み影 `0 5px 0 #C3B69C` のみで立体を出す。走査線は盤面背景だけに敷き、ミノには乗せない。

| 要素 | 実装値 |
|---|---|
| タイミング基準 | **BPM 174**（1拍 ≒ 345ms）。UI跳ね=1/2拍、点滅=1拍、フィーバー脈動=2拍 |
| ライン消去 | 列遅延**30ms**（左→右）／1セル210ms `cubic-bezier(.2,1.5,.35,1)`／scale 1→1.34→0／10列で480ms |
| 段落下 | 230ms `cubic-bezier(.22,1,.36,1)`、9%オーバーシュート |
| ハードドロップ | 落下110ms／着地スカッシュ260ms／衝撃波140ms／破片5〜9個420ms |
| 爆弾 | 左下端から列遅延26ms・行遅延14msで右上へ波及／飛散420ms＋回転320°／全画面フラッシュ70ms・最大85% |
| 重力 | 列遅延32ms／1ブロック270ms `cubic-bezier(.34,1.3,.5,1)`／着地9pxバウンド |
| フィーバー | 突入260ms スラムイン／継続中460ms周期で-16px跳ね（要素ごと70ms遅延）／終了600ms減衰 |
| コンボ | 260ms `cubic-bezier(.2,1.6,.3,1)` で scale 1→1.5→.94→1、±4°首振り。段階で44/60/78/96px に昇格、20以降は点滅 |

**画面シェイク**（盤面ラッパーにのみ適用。筐体とHUDは固定＝酔い対策）

| 契機 | 振幅 / 時間 |
|---|---|
| 1列消去 | 4px / 90ms |
| 2列 | 8px / 140ms |
| 3列 | 13px / 200ms |
| 4列（TETRIS） | 20px / 300ms ＋ 回転0.7° |
| 爆弾3〜4 | 26px / 380ms ＋ 回転1.0° |
| ハードドロップ着地 | 6px / 110ms |

減衰は振幅を毎回 ×0.62。設定に「画面揺れ 0〜150%」スライダを用意する。

**フィーバー中のディスコ演出**（デザイン仕様からの拡張）

盤面の内側だけをディスコの照明にする。クリーム筐体には波及させない。

- 盤面背景を1/2拍ごとに巡回する6色で塗り、明るさを拍で脈動させる
- 対向色のスポットを2拍周期で斜めに走らせ、単色べた塗りに見せない
- **積んであるミノ全体を市松状に2色で明滅**させ、左上から右下へ波を流す
- コンボ数字は1.5拍で色が飛び、1/2拍で点滅する
- 暗いパネルの枠と発光色が3拍周期で切り替わる
- 設置スプラッシュとハードドロップの火花が虹色になり、数が1.8倍になる

強度は既存の「フラッシュ / 点滅」スライダに連動する。0にすれば全て消える。

### 3-6-2. HYPE MOMENTS（デザイン仕様 05）

演出の山場。数値はすべてデザイン仕様のまま実装している。

**T-SPIN** — 回転→固定を1フレームで止める
- はまった穴の形に沿う白枠が `scale 1.75 → 1.00`（140ms）で収縮、線幅 6→2px、その後320msでフェード
- 紫フラッシュ60ms ＋ 破片6〜10片を全方位へ560ms
- バッジは `scale 2.2 → 1` のスラムイン（150ms）＋2°の首振り、0.9秒保持して上へ抜ける
- SINGLE/DOUBLE/TRIPLE で枠色をシアン→マゼンタ→ゴールドに昇格
- シェイク 10px / 160ms

**4列消し（TETRIS）** — 左からのポップとは**別演出**
1. チャージ240ms: 4行が下から順（55ms差）に brightness 1→3.4／彩度0へ白飛び、scaleY 1.16 に膨らむ
2. 白い横スイープが4行を200ms `cubic-bezier(.4,0,.2,1)` で貫通
3. スイープ通過後140msで scaleY 0.24 → 0 に圧縮消滅
- 金色リングが横楕円で拡散（280ms）＋盤面下から光の柱（340ms）
- 文字は skew -8° で `scale 2.6 → 1` スラム（170ms）、0.85秒保持
- シェイク 20px / 300ms ＋ 回転0.7°
- **落下再開は圧縮完了から60ms後**（タメを作る）。このため消去ディレイは通常710msに対し **870ms**

**スコアポップ** — 消した場所に叩き出す
- 出現位置は消えた行の重心。盤面座標に紐づける
- `scale 3.4 → 1.0`（blur 6px→0、180ms）→ 1.16 のオーバーシュート → 0.85秒保持 → 上へ72px移動しながらフェード（計1.6s）
- 内訳タグは80ms差で下から順にライズイン
- **2列以上のみ**表示。段階色は 2列シアン／3列マゼンタ／4列・T-Spin ゴールド＋金縁
- フィーバー中は文字がビート（345ms）で微振動

**イベント消去VFX（4種）** — ポップ消去がそのタイルに到達したフレームで発火
| 種別 | 演出 |
|---|---|
| 爆弾 | 二重の衝撃リング（マゼンタ→イエロー、80ms差）が380msで3.1倍に拡散。破片8個を放物線で480ms。赤フラッシュ50ms。シェイク8px |
| ハート | ピンクのオーラが420msで膨張。ハート4〜6個が90ms差でふわり上昇（720ms、横に蛇行）。**爆発感を出さず回復のニュアンス**。シェイクなし |
| コイン | 金貨4〜6枚が rotateY 1080° しながら左右に散って落下（760ms）。金の水平ラインが500ms残る |
| クローバー | 緑の光柱が340msで立ち、星が螺旋を描いて外へ（760°回転・820ms）。4種で最も長い |

同一ライン内に複数ある場合は左から順に連発し、**3個目以降はVFXを50%に間引く**。

**フィーバー現金砲**
- フィーバー中のみ、**4拍ごと（1.38s）に左右交互**発射。左砲が拍1、右砲が拍3
- 1斉射6〜8個を120ms差で射出（マズルフラッシュ90ms）
- 弾種5種（金貨大小／銀貨／札束／紙幣）。放物線2.76s `cubic-bezier(.25,.6,.5,1)`、頂点は画面高の60〜85%
- **盤面の手前・HUDの奥**（z-index 8）。盤面に重なる区間だけ不透明度0.55
- コンボ10+で8個、20+で10個。クローバーフィーバー中は札束の比率を上げる
- 同時40個上限。フィーバー終了で新規停止、飛んでいる分は落ちきるまで再生
- 設定「パーティクル量」0%で完全OFF

**タイポグラフィ**: Bungee（COMBO・見出し・FEVER）／Press Start 2P（スコア・数値・ラベル）／DotGothic16（日本語本文）

**グリッド**: セル28px（実体26＋隙間2）／盤面 10×20 ＝ 280×560／サイドパネル幅250／枠線3px固定／角丸はベゼルのみ12px。
画面全体は 1120×720 の固定設計とし、ビューポートには等倍スケールで収める。

### 3-7. 自動品質調整（QualityManager）

演出強度の手動設定に加え、実測fpsによる自動軽量化を行う。

```
監視: 直近120フレームの平均フレームタイム
降格: 16.67ms超過が連続したら1段階下げる（ヒステリシス付き、頻繁な振動を防止）
復帰: 余裕が一定時間続いたら1段階戻す
段階: ULTRA → HIGH → MID → LOW
```

段階ごとに変化するパラメータ:

| パラメータ | ULTRA | HIGH | MID | LOW |
|---|---|---|---|---|
| パーティクル同時数上限 | 420 | 260 | 120 | 0 |
| 画面揺れ倍率 | 1.0 | 0.85 | 0.6 | 0 |
| フラッシュ倍率 | 1.0 | 0.85 | 0.6 | 0.3 |
| イベントタイルの外側glow | ON | ON | ON | OFF |
| ソフトスキャン光 | ON | ON | OFF | OFF |
| ライン消去の白リング | ON | ON | OFF | OFF |
| 背景アニメーション更新頻度 | 60Hz | 60Hz | 30Hz | 15Hz |

デザイン仕様の指定は120個だったが、これは DOM 描画を前提とした値だった。
Canvas では `fillRect` が主体で余裕があるため実測のうえ引き上げてある。超過分は破棄する。
フィーバーと爆発が同時発火している間はさらに50%間引く。

**実測（盤面ほぼ満杯＋フィーバー＋パーティクル361個＋現金砲25発、300フレーム）**
p50 0.7ms / p95 5.1ms / 予算超過フレーム 1%。60fps予算 16.67ms に収まる。

イベントタイルの glow は `shadowBlur` を毎フレーム実行すると非常に重く、
フィーバー中（L3=44px）に予算を割ったため、種別と発光段階ごとに一度だけ
オフスクリーンへ焼いて以後は転送する方式にしてある（`blocks.ts` のスプライトキャッシュ）。
見た目は変えずに p95 を 19.1ms → 5.1ms に改善した。

**ユーザー設定（3e CONFIG）** — これが自動調整の上限キャップになる

| 項目 | 範囲 | 既定 |
|---|---|---|
| 画面揺れ | 0〜150% | 120% |
| パーティクル量 | 0〜100% | 100% |
| フラッシュ / 点滅 | 0〜100% | 85% |
| 走査線ノイズ | OFF / 弱 / 強 | 弱 |
| マウス追従の滑らかさ | 0〜1 | 0.35 |
| 自動品質調整 | ON / OFF | ON |

- `prefers-reduced-motion` 検出時は振幅・点滅を 1/4 に落とす
- アニメーションは `transform` / `opacity` / `filter` のみを使う。`box-shadow` アニメは同時5要素まで
- 全エフェクトは `LOW` で完全無効化してもゲームプレイが成立すること

### 3-8. サウンド

- Web Audio APIによる完全プロシージャル生成。矩形波（デューティ比 50/25/12.5%）・三角波・ノイズの3系統だけで全音を作る
- **`AudioSource` 抽象レイヤ**を挟み、`soundManifest.ts` でキューごとに「合成」「音源ファイル」を切り替え可能にする。差し替え時にゲームロジックは一切変更不要
- 初回ユーザー操作でAudioContextを解放（ブラウザの自動再生制限対応）
- SEバスとBGMバスを分離し、マスター／効果音／BGMを個別に調整。出力段に軽いリミッタを入れて音圧を稼ぐ
- 同一キューの連打は最小発音間隔で間引く（移動音など）。ただし予約発音（消去ポップ）は対象外

**BGM**: BPM 174 の16分グリッドで、ベース・アルペジオ・キック・ハイハットを鳴らす16ステップのループ。
フィーバー中は上物のリードが加わり、各パートの音量が上がる。
ルックアヘッド方式（200ms先まで予約）で、`setInterval` のジッタに関係なくサンプル精度のリズムを保つ。

**発火点**（デザイン仕様で確定）: 移動／回転／ソフト着地／ハードドロップ／各列ポップ（左→右で音程上昇）／
爆発／重力着地／フィーバー突入・終了／コンボ加算（段階でピッチ上昇）／スタック取得・ロック・発動・不発／
レベルアップ／ゲームオーバー／UI操作

**拍同期**: `AudioEngine.getBeatPhase()` が返す拍内位相を毎フレーム描画層へ渡し、
盤面グリッドの明滅とフィーバー中の背景脈動を曲のビートに一致させる。BGM停止中は内部時計で代替する。

## 11. 対戦ルール（第2弾）

**方針**: 標準テトリス準拠のおじゃまを土台に、イベントスタックの発動を追加の大技として上乗せする。

### 11-1. ライン消去による攻撃

| 消去 | 送信行数 |
|---|---|
| Single | 0 |
| Double | 1 |
| Triple | 2 |
| Tetris | 4 |
| T-Spin Mini | 0 |
| T-Spin Single | 2 |
| T-Spin Double | 4 |
| T-Spin Triple | 6 |

- Back-to-Back 成立で **+1**
- コンボ加算 `[0,0,1,1,1,2,2,3,3,4,4,4,5]`（コンボ数で引き、表を超えたら最終値）
- パーフェクトクリアで **+10**
- 1回の設置で送れるのは **最大12行**（即死を防ぐ）

### 11-2. イベントスタックによる攻撃

| 種別 | 対戦での役割 |
|---|---|
| 爆弾 | 消し飛ばした行数と同じだけ相手へ送る（最大の攻撃手段） |
| クローバー | 直接は送らず、フィーバー中の攻撃倍率を上げる（×2で1.2倍、×4で1.5倍） |
| ハート | 攻撃しない。到着待ちのおじゃま除去と重力による立て直しの札 |
| コイン | 攻撃しない。落下速度を落として自分を立て直す札 |

ソロで確立した「溜めて撃つ」駆け引きが、そのまま対戦の軸になる設計。

### 11-3. 相殺と受信

- 自分の攻撃は、まず自分が受けている未挿入のおじゃまを打ち消す。残りだけが相手へ届く
- 受けたおじゃまは **900ms の猶予**を経て盤面下部へ挿入される。この間に消去すれば相殺できる
- おじゃま行は1マスだけ穴が空く。穴の位置は決定論的に決め、全プレイヤーで一致させる
- おじゃまブロックは無彩色（`#6b6157`）で描き、自分の積みと区別できるようにする

### 11-4. 勝敗

**サバイバル**。最後まで生き残った1人が優勝。先に力尽きた人ほど下位になる。

時間経過だけでもレベルが上がる（**25秒ごとに+1**）。ライン数によるレベルとの高い方が採用されるため、
消さずに耐えているだけでは逃げ切れない。ソロのエンドレスではこの加速は無効（従来どおりライン数のみ）。

※ 制限時間内のスコア勝負は将来のモードとして残す。

### 11-5. 通信の構成

```
クライアント（決定論的コア） ←→ サーバー（部屋と中継のみ）
```

**サーバーはゲームロジックを持たない。** 各クライアントが同じシードで決定論的なコアを回し、
サーバーは「誰が誰へ何行送ったか」と「盤面スナップショット」を配るだけ。
ローカル対戦にはこれで十分で、不正対策が必要になった段階でサーバー権威型へ寄せられるよう
`core` は純粋なまま保ってある。

| 項目 | 内容 |
|---|---|
| 実行 | `npm run server`（Node の TypeScript 直接実行。ビルド不要） |
| ポート | 8787（`PORT` 環境変数で変更可） |
| 通信 | WebSocket（`ws`）。JSONメッセージ |
| プロトコル | `src/net/protocol.ts` にクライアントとサーバーの共有定義 |
| 部屋 | 最大4人、4文字コード（紛らわしい `O/0/I/1` を除外） |
| 盤面共有 | 200msごとに1文字1セルの文字列で送信 |
| 生存確認 | 5秒ごとの ping、15秒無応答で切断 |

ホストは最初に入った人。抜けたら次の人へ自動で引き継ぐ。ルール変更と開始はホストのみ。

### 11-6. 画面と流れ

```
MENU → ROOM ─→ [LOBBY] 部屋作成 / 参加 / READY / ルール / チャット
                  ↓ 全員 READY → カウントダウン 3
               [VERSUS] 自分の盤面＋右に相手の縮小盤
                  ↓ 決着
               順位表（勝者は WINNER!）
                  ↓ ロビーへ戻る
               [LOBBY] READY がリセットされ、同じ顔ぶれで再戦できる
```

- 相手の縮小盤は 200ms ごとのスナップショットで描く。おじゃま受信量は右端のゲージ、
  フィーバー中は縁が光り、脱落者は暗転して `K.O.` を出す
- 決着しても対戦画面は閉じない。順位表を見てから自分の操作でロビーへ戻る
- 攻撃の相手は、生き残っている相手からランダムに1人選ぶ

### 11-7. おじゃまの演出

| 契機 | 演出 |
|---|---|
| 受信 | 盤面上部に `INCOMING n` の赤い点滅バナー。盤面右端に行数ぶんの縦ゲージ（3本以上でマゼンタ、6本以上で赤） |
| 着弾が近い | ゲージの点滅が速くなり、盤面下部が赤く染まる |
| 着弾 | 画面揺れ＋床から突き上げる赤い光＋火花。**穴の位置だけシアン**にして退路を示す |
| 送信 | 盤面右外へ `+n` が飛んでいく |

音も3種追加（受信＝低く不穏／着弾＝突き上げる重低音／送信＝抜けの良い上昇音）。行数に応じてピッチが変わる。

### 11-8. 対戦リザルト

順位・各プレイヤーのスコア／ライン／最大コンボ・自分のスコア内訳・イベント使用回数・フィーバー合計を表示する。
相手の成績は専用メッセージを足さず、200msごとに流れている盤面スナップショットから引く。
- ユーザー登録・認証・サーバー・オンラインランキング
- エンドレス以外のモード（スプリント、タイムアタック等）
- 実績・アンロック要素

## 6. 技術要件

| 項目 | 採用 |
|---|---|
| ビルド | Vite + TypeScript（strict） |
| UI | React 19（メニュー・HUD・設定・画面遷移） |
| 盤面描画 | Canvas 2D（ブラウン管の中身のみ。筐体は DOM/CSS） |
| ポストエフェクト | **不要**（下記参照） |
| ゲームループ | React外の固定タイムステップ（60Hz論理）＋ rAF補間描画 |
| 状態管理 | Zustand（UI層のみ。コアロジックは非依存） |
| 保存 | localStorage（ハイスコア／キーバインド／設定） |
| テスト | Vitest（コアロジックの純関数を対象） |

**WebGLポストエフェクトを取りやめた理由**

当初はCRT・ブルーム・色収差をWebGLの1パスで掛ける想定だったが、確定したデザインは
「光るのはブラウン管の中だけ」「走査線は弱め、ミノには一切かけない」「画面全体を覆う濃い黒線は廃止」
という方針であり、必要な表現は **走査線＋ソフトスキャン光＋イベントタイルの3段階glow** に限られる。
これらは Canvas 2D の `shadowBlur` と矩形塗りで十分に再現でき、
全画面シェーダーを通すとむしろクリーム筐体まで発光してしまい設計意図に反する。
よってポストエフェクト層は実装しない。将来必要になった場合も、盤面キャンバスにのみ適用する。

### 将来のマルチ対応のための設計分離（MVP時点で実施）

```
src/
  core/     純粋なゲームロジック。DOM/Canvas/Audio非依存、決定論的、seed付きRNG
            入力は「コマンド列」として受け取る（後でネットワーク同期に転用可能）
  render/   Canvas2D描画 + WebGLポストエフェクト + パーティクル + QualityManager
  audio/    AudioSource抽象 + シンセ実装
  ui/       Reactコンポーネント
  input/    キーボード/マウス → コマンド変換、キーバインド管理
```

## 7. データ構造（主要部）

```ts
type EventKind = 'bomb' | 'heart' | 'coin' | 'clover';

type Cell = { color: MinoType; event: EventKind | null } | null;

type EventStack = {
  kind: EventKind | null;   // カレント種別（null = 未ロック）
  count: number;            // 0-4（ハート・コインは最大3）
  cooldownUntil: number;    // ms
};

type GameState = {
  board: Cell[][];          // 10 x 22
  active: {
    type: MinoType;
    rot: 0 | 1 | 2 | 3;
    x: number;
    y: number;
    eventCellIndex: number | null;
  };
  hold: {
    type: MinoType;
    eventCellIndex: number | null;
    eventKind: EventKind | null;
  } | null;
  holdUsed: number;         // 1ミノにつき最大1回
  next: MinoType[];         // 5
  stack: EventStack;
  fever: {
    until: number;          // フィーバー全体
    cloverUntil: number;    // クローバー係数上昇だけの終了時刻
    comboRate: number;      // 通常0.15。クローバー中はコンボごとに上昇
    comboRateStep: number;  // 0 / 0.05 / 0.15
  };
  slow: { until: number; rate: number };         // 0.10 / 0.15 / 0.20
  score: number;
  level: number;
  lines: number;
  combo: number;
  rngSeed: number;
  status: 'playing' | 'paused' | 'over';
};
```

保存データ（localStorage）: `highscores: {score, lines, level, date}[10]` / `keybinds` / `settings`

## 採用した重要な判断

- ソロ完成を最優先し、マルチはコアロジックの分離だけ済ませて第2弾へ
- イベントスタックは「種類ロック＋異種無視」。狙った種類を揃える戦略性と、破棄キーの存在意義が両立する
- 効果は最高段階のみ適用（テーブル忠実）。未定義段階は直下へフォールバック。ただしハート3だけはハート1のおじゃま除去も併せて発動
- マウスは横位置決定のみ。回転・ドロップはキーボードで誤操作を防ぐ
- 音は全合成で作り、後から差し替えられる抽象レイヤを挟む
- 演出強度は手動キャップ＋自動品質調整の二層構成にする

## 実装前に残っているリスク

- 演出MAXでのフレーム落ち（QualityManagerとパーティクル上限管理で対処）
- イベント効果のバランス崩壊、特に爆弾4（`balance.ts` に外出しして即調整可能にする）
- Canvas2D→WebGL合成の実装コストが想定を超える可能性（ポストエフェクトは後付け段階実装で回避）
- ブラウザの自動再生制限（初回操作で解放する導線を必ず置く）
