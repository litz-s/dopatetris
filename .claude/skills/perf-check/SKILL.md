# パフォーマンス検証

60fps（フレームあたり16.67ms）予算を満たしているかを実測で確認する。推測で「たぶん軽い」と書かない。

## 手順

1. `npm run build && npm run preview` でプロダクションビルドを起動する（devビルドは計測に使わない）
2. Browserツールでプレビューを開く
3. `javascript_tool` で計測用スクリプトを注入し、以下を取得する
   - 直近300フレームのフレームタイム分布（平均 / 中央値 / p95 / 最大）
   - 16.67msを超えたフレームの割合
   - 描画中のパーティクル実数と `QualityManager` の現在段階
4. 引数で段階が指定されていればその段階に固定して計測する。省略時は `ULTRA` → `HIGH` → `MID` → `LOW` を順に計測する
5. 負荷が最大になる状況を必ず再現して計測する
   - テトリス（4列同時消し）
   - 爆弾4の発動（4列削除＋フィーバー）
   - フィーバータイム中の高コンボ

## 判定基準

| 指標 | 合格ライン |
|---|---|
| p95 フレームタイム | 16.67ms 以下 |
| 16.67ms超のフレーム割合 | 5% 以下 |
| 最大フレームタイム | 33ms 以下（2フレーム落ち以内） |
| 自動降格の発生 | ULTRA固定時に降格条件を満たすなら、そのシーンを要最適化と報告 |

## 報告

段階ごとの数値表と、予算超過している場合はボトルネックの推定（パーティクル数 / ポストエフェクトのフィルレート / ロジック更新 / GC）を示す。数値を伴わない「改善しました」という報告はしない。
